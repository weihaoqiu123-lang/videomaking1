# 业务组原始视觉融合设计说明

## 目标

将业务组 IT 交付包中的作品展示页视觉系统移植到现有量子系统 Demo，替换当前作品集页面的视觉外壳，同时保留已经确认并实现的服务数据、作品集规则、制作人状态逻辑和四阶段下单流程。

最终效果不是两个独立网站，也不是 iframe 嵌套：用户仍在同一个量子系统 Demo 中完成“查看作品 → 选择服务 → 进入下单 → 自动带入类型 → 提交需求”的完整流程。

## 实施边界

### 直接继承业务组原始视觉

- 全屏媒体 Hero、深色遮罩、居中巨型标题、顶部作品集导航及滚动提示。
- 背景视频及静态降级封面；不再使用当前同心圆占位图形。
- 深色作品展示区的大字号编辑式排版、横向作品流和分类型作品卡片。
- 深色作品区与浅色服务价格区的页面节奏。
- AI 服务的大型三档价格卡，以及其他标准服务的紧凑卡片布局。
- 制作人区域的深色圆角容器、插画头像、横向滑动大卡片、状态标签、代表作品和排队信息。
- 原页面的荧光绿色、黑色、纸张浅色、字号比例、圆角规则和基础动效。
- 原页面的响应式与 `prefers-reduced-motion` 降级行为。

### 保留现有量子 Demo 业务能力

- 顶部量子系统角色导航和角色切换。
- 首页、作品集、服务价格页和下单页的统一服务名称与顺序。
- 近期热门视频的三个演示作品、播放量/销售指标及一个月统计周期。
- 产品 AI 展示视频的“标准版 / 创意版 / 定制版”标签切换，每档三个静态占位作品。
- UGC 作品的 9:16 展示比例。
- 点击作品后打开播放弹窗，支持关闭按钮、遮罩、Esc、停止播放以及作品信息展示；弹窗内不提供下单入口。
- 制作人状态由任务数自动计算；制作人区域只展示信息、作品和排队情况，不直接下单。
- 当前四阶段下单流程、服务专属字段、价格计算、加急价格、制作人类型联动、爆满禁选和费用摘要。

### 不继承的旧逻辑

- 原 IT 页面中的“参考此作品下单”和“由 TA 制作”等直接下单按钮。
- 原 IT 页面中过期的服务名称、价格、服务顺序和任务量文案。
- 独立联系人或专项需求联系人展示。
- iframe、第二套导航、第二套作品数据或第二套订单状态。
- 为了视觉迁移而更换现有 Vite/React 技术栈。

## 页面结构

### 量子系统外壳

量子系统 Header 保持现状，作品集页面在 Header 下方使用业务组原始页面的视觉。作品集内部导航滚动到作品、服务和团队区；“进入下单系统”通过现有应用状态进入下单页面。

### Hero

Hero 使用原 IT 包的全宽视频媒体层和静态图片降级方案。标题改为已确认的“HOOYA 视频制作服务页”，说明文字使用最终业务文案。主按钮为“查看作品”和“进入下单系统”。视频不可用、加载失败或用户偏好减少动效时，显示静态封面。

### 近期热门与作品分类

在 Hero 后保留“近期热门视频”，视觉调整为原页面的大画面作品卡和编辑式指标排版。完整作品区使用原页面的标题、作品流和分类节奏，但数据来自现有 `portfolioData`。

分类按以下顺序展示：

1. 产品 AI 展示视频
2. 产品实拍展示视频
3. 社媒 UGC 广告
4. 产品 AI 精品广告
5. 产品安装视频
6. 纯剪辑任务

每个分类只保留“创建此类型视频需求”，点击后进入现有下单页并预选对应类型。产品 AI 展示视频保留三档标签；UGC 使用竖屏卡片比例。

### 服务与价格

该区域使用原页面浅色纸张背景。产品 AI 展示视频作为大型三档重点服务卡；其余五个标准服务使用紧凑卡片；“定制 / 专项需求”使用底部横向深色卡片。所有价格和说明从现有 `SERVICE_CATALOG` 读取。

### 制作团队

恢复原 IT 页面插画头像与横向成员卡片。成员姓名、能力、当前任务数、自动状态、排队提示和代表作品来自现有数据。点击代表作品打开作品弹窗，不直接进入下单。

### 下单页面

不重写业务流程，只把视觉语言统一到业务组页面：黑色/纸张浅色分区、荧光绿主按钮、编辑式大标题和一致圆角。四阶段结构、字段切换提醒、自动定价、制作人过滤与摘要保持现有行为。

## 数据与交互

- `PortfolioView` 继续通过 `onNavigateToOrderCreate(serviceId)` 与应用状态通信。
- `App` 继续负责作品集、下单页和角色页面之间的切换。
- `OrderCreateView` 接收 `preselectedVideoTypeId`，从作品分类或服务卡进入时自动选中对应服务。
- 作品弹窗继续使用现有 `findPortfolioWork` 数据查找，不新增第二份作品数据。
- 原 IT 包中的展示图片和插画资源复制到当前项目 `public` 下的独立目录，避免依赖另一个解压目录。
- 外部视频失败时不得造成空白 Hero；静态封面始终可用。

## 可访问性与响应式

- 所有按钮使用真实 `button` 或应用内导航，不用无语义可点击容器。
- 作品弹窗保留 `role="dialog"`、Esc 关闭、遮罩关闭和关闭后停止播放。
- 横向成员区支持按钮滚动、触控滑动和键盘聚焦。
- 文字与背景保持可读对比度；荧光绿主要用于强调和操作，不用于大段正文。
- 兼容桌面和移动布局；移动端不保留强制横向溢出。
- `prefers-reduced-motion` 下关闭循环位移和强动效。

## 测试与验收

### 自动测试

- 作品分类顺序、服务名称和 AI 三档数据测试继续通过。
- 新增页面交互测试，验证服务入口向下单页传递正确的 `serviceId`。
- 验证制作人代表作品点击只打开作品弹窗。
- 验证 Hero 视频失败时保留静态封面语义和内容。
- 下单价格、加急价格、服务字段与制作人负载测试继续通过。
- TypeScript 检查和生产构建通过。

### 视觉验收

- Hero 与业务组原始页保持同一构图：全屏媒体、巨型居中标题，不出现同心圆。
- 制作人恢复插画头像和横向大卡片，不出现当前写实照片双列卡片。
- 页面具有深色作品区、浅色服务区、深色团队容器的完整层次。
- 量子系统 Header、热门视频和新版业务内容仍然存在。
- 从每个作品分类和服务卡进入下单页时，类型预选正确。
- 1440px 桌面和 390px 移动宽度下无阻塞内容的横向溢出。

## 完成标准

在同一个本地 Demo 地址中，可以从量子系统打开采用业务组原始视觉的作品集，查看热门作品、分类作品、价格和制作团队；随后从相应入口进入新版四阶段下单页，并正确带入服务类型。自动测试、类型检查、生产构建和关键桌面/移动截图验收全部通过。
